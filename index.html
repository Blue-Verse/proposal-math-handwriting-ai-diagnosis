핵심 요구사항 분석

  • 학생용 모바일 웹 — 문제·손글씨 풀이 촬영/업로드 → 인식·정오 판정 → 오류 구간·오개념 진단 → 단계적 힌트(정답 비공개) → 재풀이·재평가 → 유사 복습 문제
  • 교사용 PC 웹 — 학생별 오답·재풀이 이력, 수업 준비 화면(취약 개념·반복 오답·재풀이 상태·설명 필요 여부), AI 진단 검수와 수정 이력 기록
  • 학부모용 — 요청한 학부모 대상 학습 리포트
  • AI 오류 방지 — AI 진단 × AI 독립 풀이 교차검증, 불일치·저신뢰 결과는 교사 확인 대상으로 자동 분류
  • 개인정보 보호 — 외부 AI에는 익명 학생 코드와 풀이 데이터만 전달, 식별정보와 분석결과 분리 보관, 역할별 접근 권한, 보관·삭제 기준
  • 기존 MVP 점검·오류 보완과 DB 신규 구축, 지원 종료 후 대표 직접 운영이 가능한 구조와 문서
  • 가장 중요한 선정 기준 — 학년·단원·수준에 맞는 유사 문제 생성 설계와 품질 확보·검증 방법

제안 포인트

1) 유사 문제 생성 — “구조화 요청 + 소량 시드 예시 + 자동 검증” 혼합 방식 권장

문제 DB를 크게 구축하는 방식은 이번 예산·기간과 범위 제외 항목(자체 문제은행)에 맞지 않고, 키워드만으로 요청하는 방식은 학년 범위를 벗어난 개념이나 정답 오류가 섞일 위험이 큽니다. 두 방식의 장점만 취해 아래 파이프라인으로 설계합니다.

단계내용
① 문제 프로파일 구조화오답 진단 결과에서 학년·학기, 교육과정 단원(성취기준 코드), 핵심 개념, 오개념 유형, 문항 형식, 수 범위, 목표 난이도(원문항과 같은 수준 / 한 단계 쉬운 수준)를 JSON 프로파일로 추출
② 단원 가드레일단원별 “허용 개념 / 사용 금지 개념” 목록(예: 중1 일차방정식에서 연립·이차식 금지)을 프롬프트와 검증기에 동시 적용
③ 소량 시드 예시문제은행이 아니라 파일럿 대상 학년의 주요 단원별 유형 템플릿 3~5개를 교사진이 입력(교재 원문 저장 없이 유형만) → Few-shot 예시로 사용해 말투·난이도를 학원 수준에 맞춤
④ 변형 수준 제어숫자 변형 → 맥락 변형 → 구조 변형 3단계 중 오개념 유형에 맞는 변형을 선택, 문제·정답·풀이·사용 개념을 구조화된 형식으로 생성
⑤ 자동 검증(a) 다른 AI 호출이 문제를 독립적으로 풀어 정답 일치 확인 (b) 수식 검산 엔진으로 계산 결과 재확인 (c) 루브릭 판정: 단원·개념 일치, 금지 개념 사용 여부, 난이도 → 불통과 시 자동 재생성(최대 3회), 그래도 실패하면 교사 승인 대기열로 이동
⑥ 교사 승인 모드파일럿 초기에는 “교사 승인 후 학생 노출”, 적합률이 확인된 단원부터 “자동 노출”로 전환하는 단원별 스위치 제공

품질 측정: 착수 2주 내 실제 학생 답안 표본과 교사진이 고른 단원으로 평가셋을 만들고, 생성 문제를 교사진이 정확성·단원 적합성·난이도 적합성·오개념 겨냥도 4개 항목(5점 척도)으로 평가합니다. 파일럿 오픈 전 “정답 오류 노출 0건(자동검증 통과분 기준), 교사 적합 판정 80% 이상”을 목표로 측정 리포트를 제출하고, 미달 단원은 교사 승인 모드로 운영합니다.

2) 진단 신뢰성 — 교차검증 + 신뢰도 라우팅

  • 손글씨 인식 → 단계별 풀이 전사(수식은 LaTeX) → AI 진단과 학생 풀이를 보지 않은 AI 독립 풀이를 별도로 실행해 정답·오류 단계를 비교
  • 일치 + 인식 신뢰도 높음 → 단계적 힌트 제공 / 불일치·인식 불확실·풀이 누락 → “교사 확인 필요”로 자동 분류하고 학생에게는 “선생님이 확인 후 알려드려요” 안내
  • 교사가 숙제 등록 시 교재 정답만 입력하는 선택 기능을 제공하면 세 번째 검증 축이 생겨 정오 판정 신뢰도가 크게 올라갑니다(선택, 협의 사항)
  • 힌트는 3단계(개념 상기 → 오류 위치 지적 → 다음 한 단계 유도)로 제한하고, 최종 정답·전체 풀이는 재풀이 이후 또는 교사 설정 시에만 공개

3) 기술 스택 — 현재 GitHub·Firebase·Vercel 유지 권장

  • 대표님이 이미 3종 서비스를 운영 중인 환경이라 인계 후 운영 부담이 가장 작고, 파일럿 15명~재원생 69명 규모에서 비용·성능 모두 충분합니다.
  • Firebase Auth(역할: 학생·교사·학부모·관리자) · Firestore(서울 리전) · Storage(풀이 이미지) · Cloud Functions(AI 호출·익명화·검증 파이프라인) · Vercel(Next.js 화면)
  • AI API 키와 식별정보는 서버(Functions)에서만 다루고, 화면에서는 직접 호출하지 않습니다. AI 모델은 어댑터 구조로 분리해 모델 교체·가격 변동에 대응합니다.

4) 교사 검수 결과 활용 — 이번 범위는 “기록 + 사례 기반 반영”까지

  • 포함: 원 진단 / 교사 수정본 / 수정 사유 분류 / 오개념 태그를 구조화해 저장 → 교사가 승인한 수정 사례를 같은 단원 진단 시 예시로 자동 주입(사례 기반 반영) → 월간 오진단 유형 리포트
  • 제외 권장: 모델 미세조정(파인튜닝) — 15명 파일럿 규모로는 데이터가 부족해 효과 대비 비용이 큽니다. 데이터가 쌓이는 확장 단계에서 검토하도록 데이터 구조만 미리 맞춰 둡니다.

PRD (Product Requirements Document)

프로젝트 요구사항을 정의하고 기능 범위를 명확히 합니다.

1. 프로젝트 배경 및 목적

  • 현재: 밤 9시경 숙제 완료 → 다음 날 등원 후 채점·오답 지도까지 약 19시간 동안 오개념이 방치되고, 원생 1인당 하루 7.7분이 채점·오답 분류에 사용됩니다.
  • 목표: 숙제 직후 즉시 채점·진단 → 힌트로 그 자리에서 재풀이 → 교사는 수업 전 “누가 어디서 막혔는지” 확인 → 학부모 상담에 축적된 기록 활용.
  • 이번 단계: 1단계 MVP(답안 9건 검증)를 재원생 15명 파일럿 운영이 가능한 수준으로 고도화.
  • 성공 지표(파일럿): 정답 오류가 있는 힌트·복습 문제 학생 노출 0건 목표, 교사 확인 대기 비율·교사 수정률 측정, 재풀이 시도율, 교사 채점 시간 절감.

3. 기능 요구사항

3.1 학생용 (모바일 웹)

  • [필수] 숙제 목록 → 문항 선택 → 문제·손글씨 풀이 촬영/업로드(촬영 가이드, 크롭, 흐림 감지 후 재촬영 안내)
  • [필수] 손글씨 풀이 인식과 정오 판정, 오류 구간 표시와 오개념 진단
  • [필수] 단계적 힌트 3단계(정답 비공개) → 재풀이 촬영 → 재평가, 시도 이력 기록
  • [필수] 틀린 문제의 유사 복습 문제(자동검증 통과분 또는 교사 승인분만 노출)
  • [필수] 교차검증 불일치 시 “선생님 확인 중” 상태 표시

3.2 교사용 (PC 웹)

  • [필수] 학생별 오답·재풀이 이력(원본 이미지·AI 진단·힌트 사용 단계)
  • [필수] 수업 준비 화면: 반·학생별 취약 개념, 반복 오답, 재풀이 상태, 설명 필요 여부
  • [필수] AI 진단 검수: 확인/수정/반려, 수정 사유 분류, 수정 이력 보존
  • [필수] 교사 확인 대기열(교차검증 불일치·저신뢰), 복습 문제 승인 대기열
  • [선택] 숙제 등록 시 교재 정답만 입력(정오 판정 3번째 검증 축)

3.3 학부모용

  • [필수] 요청한 학부모 대상 주간 학습 리포트(웹 링크, 권한 확인)
  • [옵션] 카카오 알림톡 자동 발송

3.4 AI 파이프라인

  • [필수] 인식 → 진단 → 독립 풀이 → 교차검증 → 신뢰도 라우팅(힌트 제공 / 교사 확인)
  • [필수] 유사문제: 문제 프로파일 → 단원 가드레일 → 시드 예시 → 생성 → 자동 검증 → 재생성/승인 대기
  • [필수] 교사 승인 수정 사례의 사례 기반 반영, 월간 오진단 리포트
  • [필수] 모델 교체 가능한 어댑터, 프롬프트 버전 관리, 호출 로그·사용량 한도

3.5 개인정보 보호

  • [필수] 학생 계정·내부 관리번호, 외부 AI에는 익명 학생 코드 + 풀이 데이터만 전달(이미지 메타데이터 제거)
  • [필수] 식별정보 컬렉션과 분석결과 컬렉션 분리, 연결 정보는 관리자 권한에서만 조회
  • [필수] 역할별 보안 규칙(학생 본인 / 담당 교사 / 해당 자녀 학부모 / 관리자), 보관 기간 경과 데이터 자동 삭제
